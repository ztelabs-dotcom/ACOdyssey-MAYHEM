## Security-relevant behavior

The application:

- hashes and validates exact supported target executables;
- validates exact patch preimages;
- writes only declared EXE patch ranges to isolated staging copies;
- hashes and validates the exact vanilla Forge before Forge modification;
- validates the embedded Forge delta before use;
- creates hash-verified original EXE and Forge backups;
- reconstructs the modified Forge into a separate staging file;
- verifies complete staged Forge identity before commit;
- coordinates Steam EXE + Forge or Ubisoft dual-EXE + Forge installation with recovery state and rollback;
- atomically replaces/restores managed files only after validation;
- verifies committed state before a successful transaction is finalized;
- recognizes the legacy MAYHEM 1.0 state where Level Unlock modified only the EXE while the Forge remained exact vanilla;
- inspects whether relevant Odyssey executables are running and refuses mutation while the game is active.

MAYHEM 1.2 also reduces redundant Forge disk reads during one transaction. Once a Forge file has been exact-hash verified, the transaction keeps it under a file lock while it is reused. This prevents mutation between validation and use without repeatedly hashing the same 3.26 GB file. Staged and committed output identities are still independently SHA-256 verified. The explicit `VERIFY` action remains a full independent verification pass.

The installer contains no runtime networking, updater, telemetry, registry access, shell invocation, process launching, P/Invoke/native interop or third-party executable extraction.

See `SECURITY_REVIEW.md` for details.
