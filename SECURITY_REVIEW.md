# Security review notes

Date: 2026-09-02
Scope: hardened public MAYHEM installer build

## Target validation

The installer supports one exact game baseline:

- Assassin's Creed Odyssey Steam 1.5.6 / build 17083392
- `ACOdyssey.exe` size: `286453072` bytes
- SHA-256: `AC327DAD2CBBDD72A3FDA8E99CBEAB9D12AF328363E4F09BC5674BDD36B8C483`

The patch engine fails closed on unsupported size/hash/PE/preimage state.

## File mutation model

All executable mutations are manifest-driven fixed-length byte replacements declared in the embedded `patches.json`.

Before commit the engine validates:

- exact supported target identity;
- operation ranges and overlap rules;
- exact original bytes;
- staging output;
- selected patched bytes;
- target state immediately before replacement.

The engine creates a verified original backup, performs work against a staging copy, uses transactional replacement, writes a recovery journal and performs rollback when completion cannot be proven.

## Backup/state writes

The UI supports two backup-store modes:

- per-user application data under `%LocalAppData%\Narzelith\MAYHEM`;
- a `Backup` directory beside the installer.

State, recovery and hash-qualified vanilla backup data remain associated with the selected store so Restore can validate the exact original file.

## Process behavior

The hardened public source contains no `Process.Start` or `ProcessStartInfo` usage.

It calls `Process.GetProcessesByName("ACOdyssey")` only to detect whether the game is running. Apply and Restore are refused while the game process is active.

The installer does not launch the game, command shells, PowerShell, browsers, helper EXEs or other applications.

## Network behavior

Source-only audit result: no matches for runtime networking APIs or URL literals used for communication.

The hardened public source contains no:

- `HttpClient` / `WebClient` application code;
- sockets;
- runtime download/update logic;
- telemetry or analytics;
- remote configuration.

The installer performs no intentional runtime network communication.

Build-time `dotnet restore/publish` can contact NuGet only to obtain Microsoft framework/runtime packs when they are not already cached. That is a build-machine operation, not installer runtime behavior.

## Registry / shell / native interop

Source-only audit result:

- registry access: none;
- shell invocation: none;
- P/Invoke / native interop declarations: none;
- dynamic library loading: none.

## Single-file runtime extraction

The application is self-contained and published with `IncludeNativeLibrariesForSelfExtract=true` because the official .NET single-file host must materialize Microsoft native runtime components at launch.

Single-file compression is disabled.

The application does not use this mechanism to hide or launch a third-party patcher/helper executable.

## Embedded resources

Application-authored/project resources compiled into the executable:

- `patches.json`;
- installer artwork;
- installer audio;
- application icon.

No Ubisoft executable or complete proprietary game package is embedded.

## Third-party code/dependencies

`dotnet list package --include-transitive` reports no external application-package references for the installer project.

The self-contained executable includes Microsoft .NET runtime components generated by the official SDK publish process.

No UPKUtils, AnvilToolkit, Forge-builder or other third-party helper executable/DLL is present in the hardened public build.

## Privilege model

The project contains no custom elevation/bootstrapper code and does not self-elevate. File writes execute with the permissions of the user who launched the installer.
